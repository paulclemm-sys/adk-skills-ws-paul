# Challenge 2 - Enhancing Agents with Callbacks

## Objective

Enhance the ADK weather agent created in Challenge 1 by using callback functions to provide logging and input validation.

## Architecture

User Request  
↓  
Before-Model Callback  
├── Log user prompt  
├── Validate user input with Gemini Flash-Lite  
├── Validate that weather locations are within the United States  
└── Block unsafe or unsupported requests  
↓  
ADK Weather Agent (Gemini)  
↓  
Google Maps Geocoding Tool  
↓  
National Weather Service API  
↓  
After-Model Callback  
└── Log model response  
↓  
User Response

## Features

- Logs user prompts using a before-model callback.
- Logs model responses using an after-model callback.
- Writes logging information to `weather_agent.log`.
- Uses Gemini Flash-Lite as an input-validation guardrail.
- Rejects weather requests for locations outside the United States.
- Rejects unsafe or malicious user input before it reaches the primary model.
- Uses Google Maps Geocoding to convert U.S. locations to latitude and longitude.
- Uses `api.weather.gov` to retrieve National Weather Service forecast data.

## Validation Tests

The validation logic was tested with three types of input:

- **Valid U.S. location:** Boston, MA - request is allowed and weather is returned.
- **Outside the U.S.:** Paris, France - request is blocked with a U.S.-only weather message.
- **Unsafe request:** request is blocked with a content-guidelines message.
